## Задания

### 2.1. Vector2D

Двумерный вектор с вещественными компонентами. Конструктор; длина; угол с вектором-параметром; изменение текущего вектора умножением на число; сложение с другим вектором; скалярное произведение.

### 2.2. BankAccount

Банковский счёт: имя вкладчика, строковый номер счёта, баланс. Создание и инициализация; представление имени, номера и баланса строкой; пополнение; снятие заданной суммы.

### 2.3. Bank

Банк хранит список счетов из 2.2: динамический массив либо std::vector. Максимальное и текущее число клиентов хранить, если это требуется выбранной реализацией. Реализовать инициализацию списка; добавление счёта; поиск по имени; закрытие по имени; вывод клиентов со счетами; общий баланс; корректное завершение работы с объектом.

### 2.4. Vehicle, Horse, Car

Vehicle: постоянное прямолинейное движение, velocity и cur_pos в одномерном пространстве. Конструктор; get_distance(t); move(t) меняет cur_pos; move(x,t) переносит в x и пересчитывает скорость; info() возвращает сведения об объекте и позиции. Наследники Horse (name, suit) и Car (brand, color, id). Реализовать конструкторы и переопределить info().

### 2.5. Shape2D

Базовый класс двумерных фигур и наследники: прямоугольник, треугольник, круг; дополнительные фигуры — по желанию. Для базового класса и наследников предусмотреть строковую информацию, площадь, сравнение по площади с результатом -1/0/1. Реализовать конструкторы наследников и переопределения базовых методов. Перегрузить <, ==, > для сравнения фигур.

### 2.6. Vector<n,Type>

Шаблонный класс n-мерного вектора, Type по умолчанию double. Приватный C-массив компонент. Конструктор; длина; угол между векторами того же типа. Перегрузить присваивание, умножение на число, сложение и вычитание векторов одного типа.

## Что отправить

Один PR на всю лабораторную. Код и README находятся в `lab-01/` или `lab-02/` соответственно. В README лабораторной укажите выполненные задания и ссылки на исходники, точные команды сборки/запуска, проверочные примеры с ожидаемыми и фактическими результатами, известные проблемы и таблицу использования ИИ. Шаблон уже подготовлен в репозитории.

Не загружайте исполняемые файлы, .class, объектные файлы и каталоги сборки. Задания лабораторной №1 оформляйте отдельными программами; в №2 связанные классы переиспользуйте. Допустима эквивалентная понятная структура — уже работающий код не нужно переписывать только ради названий каталогов.

Если работу уже приняли ранее, всё равно оформите PR и напишите: **«Уже принято преподавателем — требуется только учёт в GitHub»**, добавив когда и как сдавали.

## Критерии проверки

Соответствие каждому условию, компиляция по указанным командам, корректность на обычных и граничных входах, предусмотренная условием обработка ошибок, полнота README и отчёта об ИИ. Искусственно создавать ошибку или получать Request changes не требуется: доработка нужна при реальных замечаниях.
